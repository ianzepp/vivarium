## 1 + 3. Node kinds, edge styles, and a widened documented Mermaid subset (high + medium)

**Schema 8** (`src/storage/schema.rs`): bump `STORAGE_SCHEMA_VERSION` to `"8"`; add to `SCHEMA_DDL` and to the repair path via `add_column_if_missing` (pattern at schema.rs:205-232):
- `work_graph_nodes.kind TEXT NOT NULL DEFAULT 'task'` — values `task` (dispatchable work, default; all backlog-minted nodes) | `decision` | `stub` | `parked` (operator-gated: never dispatched).
- `work_graph_edges.style TEXT NOT NULL DEFAULT 'solid'` — `solid` (prerequisite, gates readiness) | `dotted` (coupling: topology evidence only, never blocks readiness). **User decision: dotted = non-gating coupling.**

**Parser** (`src/mailspace/mermaid.rs`), hand-rolled, stays std-only:
- Rhombus `id{label}` / `id{"label"}` → kind `decision`. Stadium `id([label])` → plain `task` node. Dotted `-.-` / `-.->` (with optional `|label|`) → edge style `dotted`. `find_arrow` becomes longest-match over `{-.->, -.-, -->}` (note `-.->` contains `-.-`).
- `id:::name` suffix (also after `]`/`}` and inside edge endpoints) and `class id1,id2 name` statements → kind when name ∈ {decision, stub, parked}; other names ignored as styling. `classDef …` lines ignored (check `classDef` before `class` prefix). Rhombus implies `decision`; `:::` applies to rect/bare ids only.
- `MermaidNode`/`MermaidEdge`, `WorkGraphNodeInput`/`WorkGraphEdgeInput`/rows, `GraphNodeView`/`GraphEdgeView` gain `kind`/`style`; threaded through `compile_import` (graph.rs:395-424), storage inserts/selects (`src/storage/graph.rs`), `project_nodes`/`node_view`.

**Errors name the construct** (mermaid.rs): `parse_bracket_label` trailing-token and `validate_id` failures echo the offending text and append the accepted subset ("accepted: `id`, `id[label]`, `id{label}` (decision), `id([label])`, `id:::kind`, `a --> b`, `a -.-> b`, `a -->|label| b`, `subgraph/end`, `%%` comments; `classDef` styling is ignored"). Same summary goes into the `--help` long doc for `graph import` and `graph apply` (`src/cli/mailspace_command.rs:464-517`).

**Gating semantics**:
- Readiness computation unchanged (a node is ready when solid prereqs are done; dotted edges excluded from `blocked_by`/`unfinished` in `node_view`, graph.rs:601-638, and from `ready_handles`/`newly_ready_after_done` in graph_mutate.rs:620-660). Cycle detection keeps using all edges.
- `GraphFrontier` and `GraphImportReceipt` gain a `gates` list (source id + kind) partitioned out of `ready`; `graph ready` text output prints a `gates` line (`print_frontier`, graph.rs:274-333). Blocked gated nodes stay under `blocked`.
- `graph activate` refuses kind ≠ `task`: "cannot activate decision node '<id>'; operator-gated nodes are resolved with `graph complete --note`, not dispatched" (graph_mutate.rs:178-227). `graph complete` unchanged — decisions resolve by completing.
- `graph node add` gains optional `--kind` (cli/mailspace_command.rs:643-668).
- `export_mermaid` (graph_mutate.rs:679-716): decision → `id{"label"}`, stub/parked → `id["label"]:::kind`, dotted → `-.->`; round-trip preserved.

## 2. `no_done_when` legibility + parked wants + send-time warning (medium)

- `no_done_when` detail (step.rs:184-191) lists labeled fields the body does carry (e.g. "body declares no done_when clause; labeled fields present: verdict, repo") so coordination tasks read as such, not as defects. Generic `^label:` scan, capped.
- `want_requires_promotion` detail becomes "parked: wants never dispatch before explicit promotion" (+ "; body declares no done_when clause" when also clauseless). Reason vocabulary unchanged — tests and skill docs pin it.

## 4. Own-inbox lifecycle twins (medium, pre-v9)

Fix: drop the fallback — `unwrap_or_default()`; when no other local identity exists, mint only the `sent` copy, with `To:` headed to self (same header shape as today). Thread/trace evidence is preserved via In-Reply-To/References on the sent copy; `store_reply_link` already tolerates empty reply requests. Cross-identity receipts (ceo→cto done by cto → receipt in ceo's inbox) unchanged.
